## Findings

### Keep as snippets

- `jobserver_check.py`: the only check of how Ninja returns slots when killed, interrupted, or when the pool restarts. Present user: any change to Ninja or `tools/jobpool`. Keep.
- `bits_fault_injection.py`: present user is WU2's evidence; it is specific to `bits.hpp`. Keep until a general driver replaces it (below).

### Delete

- `runs_tsv_merge.py`: its index entry says to delete it at this review if no branch needs it. Every feature branch (`build`, `core-bits`, `core-metric`, `m0-scripts`, `recorder`) is merged into `develop` (`git branch --merged develop`), and `runs.tsv` on this branch has one header line and one field count (28). No branch needs it. Lesson 0001 item 4 names it as the fix for a doubled record; if it is deleted, that lesson's "what detects it now" still holds (the `grep` and `awk` checks), and the script stays in history. Recommend delete, with the index entry.
- The workbench copies of the spikes: all 26 source files are duplicates or older versions of `docs/agent/records/spikes/`, which the research notes cite. The workbench may be cleared at any time; recommend clearing `spike-a/`, `spike-b/`, and `spike-cdf/` there. `spike-cdf/memo-run.log` exists only in the workbench; research note 0011's tables come from the committed `out/memo/*.tsv`, so the log is not relied on (inferred from the note's evidence lines; not checked line by line).

### Remove from the index, because they now live in `test/` or `tools/`

The README's rule is that a snippet that becomes part of the build or the tests moves to `tools/` or `test/` and leaves the index. Three entries describe files that already did:

- `test/reference/golden.py` (the golden-header generator and check) is built into `reference.golden`.
- `tools/test_references.py` (markers, golden facts, trace, and, from this unit, citations) runs as `tests.reference_markers`, `tests.golden_facts`, and `tests.citations`, with its own fixture tests.
- `test/expect_output.cmake` was never indexed but carried "Snippet candidate" in its first line; it is the runner of every abort and compile-fail test.

Recommend removing the first two entries; the files themselves stay.

### Promote or merge, each for a unit of its own

- A general mutation driver. Three units mutated a header or a script to show their tests can fail: WU2 with `bits_fault_injection.py`, WU3 by hand, and this unit with a scratch driver that removes each line of `tools/citation_patterns.txt` in turn and runs the rejection tests (23 of 23 killed). Lessons 0060 and 0061 say what such a driver must do: assert that every anchor occurs exactly once, and report the build's exit status before the tests'. One driver, taking a file and a list of (anchor, replacement) pairs, a preset, and a test selection, would replace all three. Recommend writing it in `docs/agent/snippets/` when WU4 needs mutations, and then retiring `bits_fault_injection.py`.
- An anchored-edit helper. Every scripted edit in this unit went through `str.replace` after `assert s.count(old) == 1`, written inline each time. If the mutation driver above is written, it covers this too; otherwise a ten-line helper here would do.
- `records/spikes/spike-a/measure.py` (peak-memory launcher): superseded by `tools/measure`, which records the same quantities and more. Its index entry ("Candidate for WU1's launcher; review at M0") can be closed as superseded. The file stays where research note 0008 cites it.
- `records/spikes/spike-cdf/pinned.py` and `count_evals.py` (both marked snippet candidates in their docstrings): `pinned.py` duplicates what `taskset -c <cpu> tools/timed` with `tools/measure` now does. `count_evals.py` (counting constant evaluations in a Clang `-ftime-trace` file) has no counterpart and is the likely tool for the compile-cost work of PERFORMANCE P1 and P2 once the product generator lands (WU6). Recommend indexing `count_evals.py` as a candidate for WU6 and closing `pinned.py` as superseded.
- `records/performance/tag-value/measure_tag_value.py`: a harness comparing two spellings of a template argument. Its question was answered in WU3 (decision 0060). No present user; recommend leaving it with its record and not indexing it.
- `records/spikes/spike-a/diff_reference.py` and `spike-b/fault_injection.py`: indexed as candidates for WU6 and DoD-14. `test/reference/golden.py` now cross-checks the reference engine's routes, and the golden check's rejection test covers its failure path, so `fault_injection.py`'s remaining value is the validation of `clifford_reference.validate`; keep both indexed until WU6 decides.

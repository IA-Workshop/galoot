### Duplicates, now larger

5. **Mutation drivers (M3 item 1, unchanged and worse).** Ten `mutate.py` drivers now exist, 9 of them with the same five functions (`mutate`, `timed`, `failed_builds`, `run`, `main`): `0019-antiproducts`, `0019-linear`, `0020-duals`, `0020-rounding`, `0020-rounding-wu11`, `0021-transform`, `0021-transform-rounding`, `0022-format`, `0023-rga3`. `0020-duals` and `0021-transform` add `check_of`; `0023-rga3` adds layout and alias helpers for its mutant table; `0024-rotation-normalize` has only `timed` and `main`. `0022-format` is 328 lines, mostly table, and `0023-rga3` differs from `0021-transform` in about 160 diff lines in the part after the docstring, again mostly the table. Eight more reviewer mutant scripts under `records/reviews/` (`wu13a-review/mut.py`, `mut_delta.py`, the two `wu13b` `mutants.py`, and older ones) are of the same shape. WU13a, WU13b, WU15, and WU16 each named the general driver as a present user and each wrote another copy. Recommendation, unchanged from M3: one unit writes `tools/mutate` taking the mutant table as data; the existing drivers stay where their records cite them. Present users: the rotation and rga3 follow-ups, WU14, and every reviewer.
6. **Pinned before-and-after cost harnesses (M3 item 2).** Seven `measure.py` files now repeat `extract`, `read_last_row`, and `compile_pinned` (`antiproducts-cost`, `linear-cost`, `duals-cost`, `format-cost`, `rga3-cost`, `transform-cost`, `transform-rounding-cost`); two also repeat `oriented` and `growth_unit`, and `transform-rounding-cost` adds `flags` and `pinned`. Same recommendation: a `tools/measure` subcommand or a snippet that takes the before revision, the units, the repeats, and the CPU. WU17's P2 grid is the next user.
7. **Diagnostics sizes (M3 item 3).** Six scripts now do the same (`mutations/0019-antiproducts/diagnostics.py`, `0019-linear`, `diagnostics/wu11a`, `wu13a`, `wu15`, `wu16`; 56 to 74 lines each, differing in the source directory and list). `diagnostics/catalogue/scan.py` is a different tool (it maps each core message to its tests) and is a candidate `tools/` script of its own: it has a standing use for every new catch-all. Recommendation: fold the six into the harness of item 6, with the source directory as an argument.

### Stale paths and names

8. **rga3 moved to `galoot::presets::rga3`** (`include/galoot/presets/rga3.hpp`, `include/galoot/presets/rga3/`, `test/presets/rga3/`; plan 0025, merged at `26c8a82`). The merge updated `0023-rga3/mutate.py` and the includes under `test/CMakeLists.txt`. Three scripts that an owner would rerun still name the old paths and would fail or measure nothing:
   - `records/mutations/0024-rotation-normalize/mutate.py`: `HEADER = include/galoot/rga3/motions.hpp` (line 26) and its docstring. Its targets and test labels (`rga3_motions_test`, `^rga3\.`) still match the CMake names as `0023-rga3` uses them.
   - `records/performance/rga3-cost/measure.py` (and the committed `out/units/rga3_only.cpp`): includes `<galoot/rga3.hpp>` and compiles `test/rga3/<unit>_test.cpp`; the tests are now in `test/presets/rga3/`. The docstring calls the preset "the rga3 model".
   - `records/diagnostics/wu16/diagnostics.py`: globs `test/rga3/*_fail.cpp`.
   The READMEs and the message records (`wu16-messages.md`, `sizes.tsv`) and the review records quote the old paths and the old name "model" as history; they are records of what was measured then and should not be edited. Recommendation: one small unit repaths the three scripts and writes a one-line note in each record's README that the paths changed at plan 0025; the old name "model" becomes "preset" in script docstrings only.

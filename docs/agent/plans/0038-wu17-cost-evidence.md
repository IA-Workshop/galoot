## 10. Risks

1. **The DoD-24 circularity** (departure 3): the counts test cannot be final until D8 is ruled. Mitigation: C tests form (A) now; a D8 that admits collected plans reruns C with new expected values under W9.
2. **Clang's out-of-line kernels** fail DoD-24's "no calls" for `transform(line, motor)` and `compose` if they persist (departure 7). E2 measures what the call costs.
3. **Measurement bias and noise.** Layout and environment size can move a microbenchmark by more than the differences sought (knowledge base, measurement-bias note); the shared machine's other users are outside the lock. Mitigation: separate processes, interleaving, three environment sizes, the difference criterion fixed in E2, and sibling-busy rows.
4. **Optimizer artifacts.** A benchmark whose inputs the compiler knows, or whose results it drops, measures nothing (P6). E1's read of the benchmark loop itself, and the instruction count per operation against the expected count, catch it.
5. **Unlike comparisons.** Form (C) and Lengyel's counts assume unitized, constraint-satisfying motors; a rounded motor drifts off them (note 0022), so (C) can be faster and less accurate. F reports both.
6. **Collected plans late in the release train.** A core change after M7 would move `transform`'s rounding (K, tolerances, bit-level tests), the cost model (a new phase), and the matrix, just before WU18. Mitigation: a separate unit, and the option to defer past 1.0.
7. **The compile-record copy refuses** a tree that `ctest` touched; H copies before testing.
8. **Heavy runs on a shared machine:** G's GCC whole plans (up to 9.8 GB each) and E3's n = 16 antiproduct units. Mitigation: limited parallelism, pool status reads, no run started that free memory cannot serve (P11).
9. **New targets in every preset** (D) add build cost to every merge; P1 records it.
10. **Concurrent core units** change what is measured; E and H wait for them (step 5).

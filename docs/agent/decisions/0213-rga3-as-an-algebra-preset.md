# 0213 rga3 becomes an algebra preset, `galoot::presets::rga3`, and its tag names its blades

- Status: recorded. The layout, the namespace, the alias, and the test directory are the owner's rulings of 2026-11-08, relayed in the coordinator's brief; the word "presets" is the owner's choice of 2026-11-08. The STYLE S6 sentence (item 7) and CONVENTIONS 1.15 (item 8) are drafts awaiting the owner's confirmation of their wording (C10, C18). The other items are the implementer's choices, open to the owner and to the blind review.
- Date: 2026-11-08
- Recorded by: Claude (agent, Opus 5.5), implementer of plan 0025
- Bears on: plan 0025; decisions 0198, 0204, 0211 items 1 and 4, 0212; the WU15 hci reading's S2 and S3; STYLE S6; CONVENTIONS 1.6, 5.8, 7.2, and section 8; `format.hpp`'s names protocol (plan 0022 R3)

## Context

Decision 0211 makes named algebras convenience layers on the core and asks the rga3 tag to declare its own oriented names before the M4 gate, so that printing uses the published names (the hci reading's S2: the tag declared none, so a line printed as `{-e14: ..., -e24: ..., -e34: ..., e23: ..., -e13: ..., e12: ...}`). The owner then named the layer that holds such algebras "presets" and ruled where rga3 lives in it. In prose, "build preset" now means a configuration of `CMakePresets.json`, and "preset" or "algebra preset" a namespace `galoot::presets::*`.

## Decision

1. **Layout (owner).** `include/galoot/presets/rga3.hpp` (the umbrella), `include/galoot/presets/rga3/objects.hpp`, and `include/galoot/presets/rga3/motions.hpp`, in namespace `galoot::presets::rga3`; the tag keeps the name `algebra`; guards `GALOOT_PRESETS_RGA3_HPP`, `GALOOT_PRESETS_RGA3_OBJECTS_HPP`, `GALOOT_PRESETS_RGA3_MOTIONS_HPP`. Tests under `test/presets/rga3/`. Nothing under `include/galoot/core/` changes, and the core names no preset.
2. **Build.** The INTERFACE target is `galoot_presets_rga3`, alias `galoot::presets::rga3` (owner), with its own header set compiled header by header; the root check that every header belongs to a header set matches `^include/galoot/presets/rga3(\.hpp$|/)`. `galoot_add_test` gains an optional `DIRECTORY`, the directory under `test/` of the component's source, which defaults to the module; the five rga3 programs pass `DIRECTORY presets/rga3`. The alternative, a `test/presets/CMakeLists.txt` added as a subdirectory, moves about 200 lines of registration and the variables they share, for no gain a reader sees.
3. **Test names and labels stay `rga3.*`**, and so do the program names (`rga3_objects_test` and so on). The run selections (`ctest -L '^rga3'`), the mutation scripts, and every recorded run row name them, and `rga3.objects` still says what it tests. A label `presets` has no present use (C12).
4. **The include scan** reads the module `presets/rga3` (`galoot/presets/rga3.hpp` and `galoot/presets/rga3/`), which may include the core's headers and its own; its fixtures move to `test/tools/include_scan/galoot/presets/rga3/`, the core fixture that includes a preset header is renamed `includes_preset.hpp`, and the findings name "the rga3 preset".
5. **The move is one commit**, `git mv` and the edits the tree needs to build and pass, before any change of behavior; the wording ("preset" for "model" in comments, the README, and the scan's findings; "build preset" in the build files) is the next commit. W2 rules out a commit of the bare `git mv` alone, since the includes, guards, and registration would not build. Git follows the two headers and the tests at its default rename threshold and the umbrella at `-M20%`; the include-scan fixtures, a few lines each, show as new files.
6. **The names.** `algebra` declares `static constexpr auto names = "1 e1 e2 e3 e4 e41 e42 e43 e23 e31 e12 e423 e431 e412 e321 e1234";`, the sixteen oriented names of CONVENTIONS 1.6 and 5.8, in grade order with each grade in the order of the layouts. A point prints on e1 to e4, a line on e41, e42, e43, e23, e31, e12, a plane on e423, e431, e412, e321, a motor on e41, e42, e43, e1234, e23, e31, e12, 1, and a flector on e1 to e4 and e423, e431, e412, e321. A blade stored with the other orientation, as in a join, keeps its canonical name (CONVENTIONS 7.2). Naming only the ten blades whose name differs from the canonical one prints the same; the full list is kept because it states the preset's whole vocabulary in one place, as `format_test.cpp`'s `rga3_named` does. The test `rga3.format` was committed first and failed until the names landed; the README's printing example also prints a line (the hci reading's S3).
7. **STYLE S6, draft.** After the first sentence: "An algebra preset, a named algebra built on the core such as rga3, lives under `include/galoot/presets/<name>/`, with its umbrella header `include/galoot/presets/<name>.hpp`, in namespace `galoot::presets::<name>`." The guard example adds `GALOOT_PRESETS_RGA3_OBJECTS_HPP`; "and names no preset" follows the core's include rule; and a last sentence says a preset includes only standard headers, the core's public headers, and its own. The status line marks it a draft awaiting the owner's confirmation.
8. **CONVENTIONS 1.15, draft.** Section 8's "Flector transform" row named `test/rga3/objects_test.cpp`, which the move makes stale; it now names `test/presets/rga3/objects_test.cpp`. No convention changes. Marked a draft in the status line and the revision history.
9. **"Build preset."** The comments of `CMakeLists.txt` and `test/CMakeLists.txt` that meant a CMake configuration, the configure error for a missing `GALOOT_CHECKING`, and the help text of the `GALOOT_PRESET` cache entry say "build preset". Other files that say "preset" in that sense (`tools/timed`, `tools/measure`, `tools/runlog`, their tests, `.claude/agents/`, and one comment of `include/galoot/core/assert.hpp`, which this unit may not change) are left as they are; see Consequences.

## Options weighed

- Keep `galoot/rga3` with a forwarding header: rejected by the owner's layout; nothing has been released, so no user holds the old path (W13 asks the first release record to list it only if it was ever released).
- Rename the tests `presets.rga3.*`: consistent with the directory, but it would change every selection and recorded row for no reader's gain; rejected (item 3).
- Names in the tag versus in the layouts: the protocol of WU15 reads them from the tag only (decision 0204), so the tag it is.

## Consequences

- Users include `<galoot/presets/rga3.hpp>`, write `galoot::presets::rga3::Point<double>`, and link `galoot::presets::rga3`; `galoot::presets::rga3::translation` is still called qualified. GCC's and Clang's diagnostics now spell the tag `galoot::presets::rga3::algebra`, nine characters longer per mention than before.
- Printed rga3 values change from the fallback names to the published ones before any release, as the hci reading asked.
- Record scripts that name the old paths are left as records of their runs: `records/performance/rga3-cost/measure.py`, `records/diagnostics/wu16/diagnostics.py`, and `records/mutations/0024-rotation-normalize/mutate.py`. A rerun must change their paths first. The rga3 mutation script, `records/mutations/0023-rga3/mutate.py`, is updated and run again in this unit.
- The remaining uses of "preset" for a CMake configuration outside the two build files (item 9) are an open item for the owner: a wording pass over `tools/` and the agent role files, and the one comment in the core, which only a core unit may change.

## Context

Plan 0040 gathered five small changes before the M7 gate: forced inlining of the kernel chain with a structural test, the deletion of `detail::inverse_change`, a deleted `==` on `basis_change` that names `same_rows`, the two `TODO`s of `mv.hpp`, and the compiler-version limit catalogues moved out of the header comments. The plan fixed what each change does; this record states how each was done where the plan left a choice, where the code made the plan's reading wrong, and what the evidence found that the plan did not expect.

## Decision

### The forced inlining (part A)

1. **One macro, on the thirteen functions and no others.** `GALOOT_ALWAYS_INLINE` in `assert.hpp` is `[[gnu::always_inline]]` under `__GNUC__` or `__clang__` and empty otherwise, with a `///` comment that says what it does, why, and that it is not part of the interface. The structure test showed no call left with the thirteen attributed, so none of the one-line callers the plan named as candidates (`dot`, `truncate`, `part`, the conversion constructor, `change_basis`, `change_basis_back`) has the attribute (plan section 1 item 3, C12). No `NOLINT` is needed on the macro: clang-tidy's macro check does not flag an attribute.
   - Weighed: bare `[[gnu::always_inline]]` on each function, which repeats a vendor spelling thirteen times and has no fallback; the attribute on the callers too, which the evidence does not ask for.
2. **The structure test reads the compiler's assembly, not the object.** `rga3.kernels_inline` runs `test/tools/kernels_inline.py` on `<compiler> ... -S -o - kernels_inline.cpp`. The script fails on a `call` or `jmp` (any suffix) whose operand names a symbol of namespace `galoot` anywhere in it, so that `@PLT` and `*sym@GOTPCREL(%rip)` (a `-fno-plt` build) are caught as well as a direct call, and on a probe function that the output does not define. The flags are fixed (checking off, `-O2`, `-ffp-contract=off`, the S4 warnings); the include directories and the language standard are read as `galoot_compile_command` reads them, the standard as the last element of its output, which that function documents as last. The probe is also an OBJECT library with each tree's own flags, so that the lint preset sees it; its eleven functions are wrapped in `NOLINTBEGIN/END(misc-use-internal-linkage)`, since they need external linkage to be emitted.
   - Weighed: `nm` on the object, which cannot tell a tail jump from a reference; a fixed list of symbols to forbid, which a new chain function would escape; reading the tree's own flags, which would make the answer depend on the preset (checking on adds calls by design).
3. **The probe: E1's seven functions verbatim and four more** (K6): `sum_lines`, `reverse_line`, `dot_points`, `change_point`, which reach `detail::sum` and `run_sum`, the unary `apply` and `run_map`, `run_product` from `dot`, and `run_change`. The tag of `change_point` is a change of rigid(3) to itself that doubles e4, defined in the probe. Seven fixture tests, one more than the plan's six, give the local-entity form (`_ZZN...6galoot`) a test of its own, since criterion 1 names it.
4. **Four attributes the plan held to be guards are needed now.** Removing one attribute at a time, the plan expected `compose`, `transform_middle`, and on GCC `transform` to survive the structure test. They do not: without its attribute, `compose` is called from `compose_motors` on both compilers, `transform` from all three transform probes on GCC, and `transform_middle` from `transform_line` on Clang. Forcing a function inline moves its callers' inlining budget, as the advisory report found for `apply`. Six attributes stay guards (`run_map`, the unary `apply` with a target, `run_sum`, `sum`, `run_change`, `transform_outer`); the two `apply` overloads with no target layout are reached by no library caller (equivalent). The mutant specs keep the plan's expected verdicts, so `tools/mutate` exits 1 on them, and their README records the observed ones: the record shows the prediction beside the result.
5. **The formatter reads the macro as an attribute** (`c6efd1f`, the merge runner). Without `AttributeMacros: [GALOOT_ALWAYS_INLINE]` in `.clang-format`, clang-format took the macro for the start of a type and indented three of the attributed declarations as continuations. The line only tells the formatter what the token is; no other file's layout changes. It was made outside plan 0040's file table, in its own commit, so that the review can read it alone.
   - Weighed: leaving the formatter's output (three oddly indented declarations); the macro after `[[nodiscard]]`, which formats worse.

### `basis_change` (part B)

6. **The identities test reads the checked inverse**: `core::detail::check_change(change, source, target)`, `REQUIRE`s that its fault is `ChangeFault::none`, and reads `.inverse`. Its references are unchanged (K8).
7. **The deleted `==`**: `bool operator==(const basis_change&) const = delete; // use same_rows(a, b)`, with a `///` comment that says why and what to call. The literal fits the 80 columns with the declaration, so the formatter keeps it on the line that both compilers echo. The compile-fail rows require each compiler's own error text for a deleted function (GCC "use of deleted function", Clang "overload resolution selected deleted operator '=='"), chosen by `CMAKE_CXX_COMPILER_ID`, and the literal `// use same_rows(a, b)`. This supersedes the last sentence of decision 0235 item 1, which declared no `==` because `= delete("…")` needs C++26: a deleted declaration with a comment needs no message argument (decision 0236 item 3).
8. **P8 for part B was the whole suite**, not only the plan's `^core\.basis_change` selection, because the rga3 preset includes `core.hpp`, which includes `basis_change.hpp`.

## Consequences

- An operation of the rga3 preset compiles to the arithmetic of its terms at its call site on both compilers at `-O2`, and a call into the library that comes back fails `rga3.kernels_inline` on the compiler that makes it.
- At `-O0` each call of a forced function carries its body: E1's probe's text grows 10.3% on GCC and shrinks 1.3% on Clang.
- `a == b` and `a != b` on two `basis_change` values fail to compile with one error whose note names `same_rows`.
- The header comments no longer state compiler-version sizes; until the documentation lane's `docs/guide/limits.md` is on `develop`, their pointers name a heading of a page not yet there (plan 0040 risk 6, K10).

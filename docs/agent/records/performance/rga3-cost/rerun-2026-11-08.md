# The rga3 cost harness against `tools/compiles cost` (plan 0026, criterion 11)

Written by the plan 0026 implementer (Claude, agent, Opus 5.5) before either run, on `feature/evidence-tools`.

## Criterion, stated before the runs (P7)

The repathed `measure.py 88c9484 2026-11-08/old 3 4` and `tools/compiles cost units.toml 2026-11-08/new --before 88c9484 --cpu 4 --repeats 3` run one after the other in one session, under the timing lock, with the job pool idle and no other build of this unit running. For each unit and compiler, the two means of retired instructions differ by less than the larger of the two runs' ranges; where they do not, the flag difference that explains the gap is listed below the results. The extracted trees and objects are not committed.

## Differences known before the runs

The two routes compile the same sources in the same order (repeat, compiler, unit, tree), pinned to CPU 4, with outputs in directories of equal path length and the text units written to the same file names (`units/core_only.cpp`, `units/rga3_only.cpp`). Their commands differ in these ways, read from `measure.py` and from the build trees of this worktree:

- The includers (flags of the measure trees): `measure.py` adds `-I<root>/test -isystem <root>/include/ext`; the tool uses the compile-fail command of `rga3.translation_mixed`, which has `-I<root>/include` only. The other flags are the same (`-DGALOOT_CHECKING=0`, the five warning flags and `-Werror`, `-ffp-contract=off`, `-O2 -std=c++23`), in another order.
- The test units (flags of the debug trees): `measure.py` adds `-DGALOOT_EXPECTED_CHECKING=1`; the tool uses each unit's command from `compile_commands.json`. The other flags are the same, in another order.
- The object paths differ in name (`<out>/objects/rga3-cost_gcc_...o` against `<out>/objects/gcc_core_only_before.o`).
- The rows: `measure.py` writes `runs.tsv` (selection `rga3-cost:<compiler>:<name>`), the tool its campaign log `2026-11-08/new/runs.tsv` (selection `cost:<compiler>:<unit>/<tree>`).

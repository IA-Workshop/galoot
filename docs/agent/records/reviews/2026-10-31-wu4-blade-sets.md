## Findings

**Blocking**
- B1 (records only). The before-and-after cost record is wrong. The plan's "before" rows (gcc 0.842 G instructions, 78,720 KiB; clang 0.643 G) are `2976dcafb8e0-dirty` rows that compiled the uncommitted blade-set work, so "before" is really "after". The "unexplained" cheaper row is the real before (gcc 0.469 G on performance cores plus 0.181 G on efficiency cores, 68,992 KiB). The plan also compared only the performance-core count and ignored the efficiency-core count; retired instructions do not depend on the core, so the two must be added. Reviewer's measurement (identical flags, three runs each, both core kinds added; 2976dca against f9441f7): `#include <galoot/core.hpp>` alone gcc 0.488 G (59 MB) to 0.721 G (70 MB), +48%; clang 0.378 G (103 MB) to 0.548 G (107 MB), +45%; `smoke_test.cpp` gcc 0.650 G to 0.884 G, +36%; clang 0.477 G to 0.646 G, +35%. Most of the growth is `<string_view>` (base plus `<string_view>` alone costs 0.665 G on GCC and 0.518 G on Clang); the blade-set code itself costs about 0.03 G. Correct the plan's cost table and the anomaly note, and add a note to decision 0090 (do not rewrite it).

**Non-blocking**
- N1. `merge` and `index_of` accept a set written by hand with sign 0 or 2, or with a mask listed twice (`merge<{{1,0}}, {}>` keeps sign 0; duplicate masks are silently merged); a conflict inside one input is reported with the false message "the two sets hold one blade with opposite signs". Add a consteval validity check (signs ±1, masks distinct) to `make_merge` and `make_index_of`, each with a test, or record a decision deferring it to WU8.
- N2. Accepting n = `mask_bits` is not pinned: the mutant `N <= mask_bits` to `N < mask_bits` survives. Add `static_assert(of_grade<mask_bits, 1>.size() == mask_bits)` and `of_grade<mask_bits, mask_bits>`.
- N3. The `names_above_9` test requires the message only up to "n up to 9"; the mutant that changes its tail survives. Require the whole message.
- N4. Public members without a `///` comment: `oriented_blade::mask`, `sign`, `operator==`; `blade_set::blades`, `operator==`; `blade_name::chars`, `length` (metric.hpp documents the analogous members).
- N5. The constant-evaluation limit falls inside the supported range at default compiler limits: Clang fails `full<14>`, `of_grade<16, 8>`, and `of_grade<32, 4>`; GCC fails `full<16>`. Clang passes `full<13>`; GCC passes `full<15>`, `of_grade<16, 8>`, and `of_grade<32, 4>`. State the measured bounds in the header comment or decision 0090 so the plan generator and `mv` units do not rely on `full<N>` above n = 13.
- N6. Decision 0090 item 2 says each constructor returns a placeholder after a failed check; `make_merge` and `make_index_of` have none (still one error each). Item 1 is marked "inferred; no compile was made"; the reviewer compiled it. Add a note, not a rewrite.
- N7. The mutation records leave out the first error line of each failed build, and "every test was shown able to fail by mutation" overstates: the namespace-scope `static_assert`s on aggregates and trivially copyable types were never mutated.

Compile-fail test time: it should not hold up this merge but is worth fixing soon. The 21 rejection tests took 3.8 s (gcc-debug), 5.1 s (clang-asan), and 3.9 s (lint), about 0.2 s each and run one at a time (6.5 to 7.5 s under load). Each rejection costs one `cmake --build` under the build-tree lock, so the cost grows with the misuse catalogue. Suggestion for the build lane: compile each fail source with a direct compiler call, using the target's flags and no build-tree lock, so the tests run in parallel from the pool.

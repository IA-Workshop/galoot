## 3. My route

The record's engine is a Chevalley construction on the exterior algebra: generators act as wedge plus contraction, and coefficients are stored as index tuples. Mine uses different machinery, and none of its code comes from the record or from Galoot:

- **Matrices for the product.** I diagonalize the Gram matrix by congruence over Q, g = M D Mᵀ. Each orthogonal generator f_k is a Jordan–Wigner matrix of size 2ⁿ: Z ⊗ … ⊗ Z ⊗ [[0, D_k], [1, 0]] ⊗ I ⊗ … ⊗ I. Then e_i = Σ_k M_ik f_k, and the script asserts e_i e_j + e_j e_i = 2 g_ij as matrices. A blade is the antisymmetrized product of its generators' matrices. Coefficients are read back from the action on the vacuum vector, and the script checks that this readout is faithful. The geometric product is matrix multiplication. No bit-mask sign rule enters it, so it works the same for degenerate and non-diagonal forms.
- **Definitions for everything else.** The wedge uses the sign of the reordering (4.1). The complements are solved from u ∧ ū = 𝟙 and u̲ ∧ u = 𝟙. The exomorphism G is built by wedging the images g(e_i). The antiexomorphism is left ∘ G ∘ right. I chose that reading before I read the record's departure 3, which makes the same choice. The antiproduct, antiwedge, duals, transform, compose, project and antiproject follow CONVENTIONS 4.2 to 4.4 as written. All arithmetic is exact, in python-flint 0.9.0 `fmpq_mat`.
- **Other routes.** sympy 1.14.0 matrices over Q(√2, √3) for G17. A C++ probe that prints the parse tree of mixed operator expressions for 7.1a. Hand derivations where they were short.
- **Forms.** rigid(2), rigid(3), R(3,0,0), the diagonal form diag(1, −1, 1, 1, −1), R(2,0,2), conformal(1) to (3), R(4,1,0), the Witt form of two null pairs, R(2,2,0), dense forms of size 3, 4 and 5 (det −7, 23, and one random), and the degenerate non-diagonal form [[1,1,0,0],[1,1,0,0],[0,0,2,1],[0,0,1,1]].
- **Changes of basis for 1.8.** conformal(3) to R(4,1,0) (the change of 1.4). The Witt form to R(2,2,0). A dense 4 × 4 form under a general P with d = 3, on which the condition fails. A swap in R(3,0,0) (orthogonal, d = −1). And **rigid(3) with e4 scaled by 2**: a degenerate change on which the condition P⁻ᵀ G′ P⁻¹ = G holds with d = 2. Only a change like this can tell the factor 1/d from d (finding m1).

## 5. Findings

No row is wrong in substance. All findings are minor.

- **m1 (minor, coverage), row 1.8e.** In the record's list of 12 changes (`s1_blades_and_bases.py`), only two have |d| ≠ 1: "R(3) general P" (d = 3) and "R(1,1,1) scale e1 by 2" (d = 2). The condition P⁻ᵀ G′ P⁻¹ = G fails on both. On the first, 1.8f rules it out, since the form is nondegenerate. On the second, I computed it. So the six changes on which the condition holds all have d = ±1. When d = ±1, 1/d = d, so the record's check cannot tell "with the factor 1/d" from "with the factor d", nor 1/d² from d². The statement is still right: my degenerate change (rigid(3), e4 to 2 e4, d = 2) confirms 1/d for the antiproduct, antidot, weight dual and compose, and 1/d² for transform, project and antiproject. Recommendation: add that change, or any scaling of a null generator, to `s1`.
- **m2 (minor, scope), row 6.2.** The row says "not derived", and the Spec column's "n/d" is defined as "not derivable". One consequence of 6.2 is cheap to derive. For round points a, b, c, the flats a ∧ e5, a ∧ b ∧ e5 and a ∧ b ∧ c ∧ e5 equal the rigid objects on e1 to e4 wedged with e5, with the same coefficients. My probe confirms this on 15 random cases. I do not count the row as a wrong classification, for three reasons. 6.2 is a Study-labeled model definition. Section 6 is outside criterion 5, as the record says. And the row claims no agreement. Recommendation: K1 (the conformal probe) records this consequence, or the row's wording becomes "not derived" rather than implying that nothing can be derived.
- **m3 (minor, wording), row 6.1b.** "Agree up to the sphere's scale" hides that the undetermined factor includes the sign. With four points on the sphere, the sign follows their order (my order gave +54 σ, the record's −54 σ). The sign is exactly what section 8's "Conformal duals" row is about. Only the test's reading of Lengyel's sphere coordinates fixes it, and the row's "Not shown" column says so. Recommendation: the Spec cell could read "agree up to a factor, sign included, that 6.1 does not fix; with the test's sphere coordinates, exactly".
- **m4 (minor, wording), G17 and the 2/m worked example.** Hestenes' code fixes angles, not coordinates. So whether a library group "differs by setting" depends on the coordinates chosen for the realization. For 2/m, the realization a = e3, b = e1, c = e2 has the same angles and gives exactly the library's set (my check). Conjugating the record's realization by its own motor would do the same for −42m and 32. What the record actually shows is that each library group realizes Hestenes' code, and that it differs from the earlier rebuild's coordinates by an explicit half-turn. The README and note 0028 D11 say "for that realization", which is accurate. A sentence making the point explicit would stop a reader from taking "setting" to mean a difference from Hestenes himself.
- **m5 (minor, rendering), `rows.md` line 32 (row 1.8f).** The cell "on every change where it held, |d| = 1" has unescaped pipes. The rendered table therefore shifts the row by two columns, and the Spec column shows "E, F" instead of "agree". Row 5.7 escapes the same characters (`\|v\|`). Fix: write `\|d\|`.

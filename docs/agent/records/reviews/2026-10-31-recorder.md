## Recommendation on decision 0042 item 5

On this machine the zero is almost certainly a true zero, but the recorder does not check it per row. perf prints `<not counted>` when an event's running time is 0; the percent field `0.00` shows its enabled time was above 0 under pinning. Either the task never ran on that core type (a real zero) or higher-priority events held every counter (a false zero); with `perf_event_paranoid` 2 and `nmi_watchdog` 0 the second needs a privileged perf session, so the first is likely but assumed. Proposed check: add the software event `task-clock` to the shared events and write 0 for a `<not counted>` core type only when the other core type's running time equals task-clock's running time; otherwise write `unavailable`. Probe: the per-type running times summed exactly to task-clock in 6 of 6 runs. The same check would flag shared rows whose numeric counts are partial. Until it exists, revert item 5 to `unavailable`, since decision 0018 says unavailable is never written as zero.

### N5 (note). `git worktree list --porcelain | grep -qx` under `pipefail`

Line 119: `grep -q` exits at its first match, so with `pipefail` the pipeline's status is `git`'s SIGPIPE (141) if `git` is still writing, and the `if` then reads as "no match". `git`'s output is 7,626 bytes with 46 worktrees (less than the 64 KiB pipe buffer, so `git` finishes writing before the pipe can fill); a standalone test with `yes | head -100000 | grep -qx y` under `pipefail` returns 141 and misses the match. It would take about eight times as many worktrees to matter. Smallest fix: `git worktree list --porcelain | grep -x 'branch refs/heads/master' >/dev/null` (no early exit) or `git for-each-ref --format='%(worktreepath)' refs/heads/master` (non-empty if checked out; git 2.23 and later).

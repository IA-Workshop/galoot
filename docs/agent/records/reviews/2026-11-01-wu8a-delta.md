## 5. Findings, most severe first

### D1 (medium, blocks; test-only): the distinct storage base has no test that can fail

- Where:
  - `include/galoot/core/mv.hpp:114-119` (the base's comment: "so that no two multivector types share this base and none can be compared with another through it");
  - decision 0150, implementation item 2 (without a distinct base, "its `==` would compare a Line with any other six-blade type of any algebra");
  - `test/core/mv_test.cpp:370-372`.
- Evidence. The mutants `base_drops_alg` (`coefficient_storage<void, Blades, T, ...>`) and `base_drops_layout` (`coefficient_storage<Alg, blade_set<0>{}, T, ...>`) survive the whole suite on gcc-debug and clang-debug. Under `base_drops_alg`, `Point<double>{} == FourEuclidean{}` compiles on both compilers: my concept `eq_expr<A, B> = requires(const A& a, const B& b) { a == b; }` is true there and false at head.
- Why the test cannot see it. `std::equality_comparable_with<A, B>` also requires `std::common_reference_with<const A&, const B&>`. Two unrelated class types have no common reference, so the suite's three `static_assert(!std::equality_comparable_with<...>)` hold whatever `==` does.
- This test was already vacuous at `1a5af96`. It matters now because `af447ae` rests on this property.
- Failure scenario: a later change to `storage_for`, for example to share one base among types of equal size and so cut instantiations, would let a line of rigid(3) compare equal to an unrelated six-blade type, and every test would pass.
- Resolution. In `mv_test.cpp`, test the expression in a template context:

  ```cpp
  template <class A, class B>
  concept has_equality_with = requires(const A& a, const B& b) { a == b; };
  static_assert(!has_equality_with<Point<double>, FourEuclidean>);
  static_assert(!has_equality_with<Line<double>, Bivectors>);
  static_assert(!has_equality_with<Line<double>, Line<float>>);
  ```

  Add the `CHECK_FALSE` twins as well, and keep the `equality_comparable_with` lines if they are wanted as a record of the standard concept's answer.

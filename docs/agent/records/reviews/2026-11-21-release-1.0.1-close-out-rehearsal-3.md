## 4. The whole script, read again

- **`set -euo pipefail` with the new `case` (lines 63 to 67).** With no argument, `case $#` takes `0)` and never expands `$1`. With one argument, `$1` is set, so `set -u` does not fire. Every other count is refused. Line 137 still reads `${1:-}`, which is right after the `case`. Tested by the argument forms above.
- **`|| fail` after the command substitutions (lines 90 to 93, 109, 115).** The status of `x=$(cmd)` is `cmd`'s, and the `||` turns off `set -e` for it. So a failing `git show` prints git's own line and then the script's message, with exit 1 (six injections). A passing one still assigns the content: the full run, and `logs/60-idioms.txt` (`guarded-sub-pass`). An unguarded failing substitution, by contrast, ends with exit 128 and no message (`unguarded-sub-fail`), which is now true only of line 132 (N4).
- **The ERR trap (line 144)** fires on an unguarded failing command in step 5: `git merge` refused (exit 1), `git worktree remove` refused (128), `git tag` refused (128). Each run printed one recovery line. It does not fire for a `[ … ] || fail` comparison: there `fail` prints the message and the recovery line itself, and the trap adds no third line (parent-m, tree, and `step5-fail` in `60-idioms.txt`).
- **The INT/TERM trap (line 145)** fires on either signal during step 5, after the foreground command ends, and exits 130. It does not fire outside step 5, because it is set at line 145 and cleared at line 154. **After a success neither trap fires:** the full run and every rerun after a recovery printed no recovery line, and `after-success-fail` in `60-idioms.txt` shows a failure after line 154 ending without one. The INT exit status, 130, is the one a caller testing `$?` expects for an interrupt. For TERM, 130 differs from the 143 that `kill` and `timeout` lead a caller to expect. Because the script exits rather than dying of the signal, a calling bash loop goes on after a Ctrl-C, where it stops when the script has no trap (`logs/61-caller.txt`) (N1).
- **The here-string for the worktree list (lines 132, 133).** The listing is captured whole before `grep` reads it, so an early match can no longer cut off the writer under `pipefail` (the second rehearsal's N5). It found `master` in a 125,847-byte listing whose match is at byte 422. In that listing the old pipeline also found it five times out of five, so I did not reproduce the old miss with git.
- **The rest of the change.** `RECOVER` uses `SELF`, a path relative to the repository (N5). The push line now names every ref in full and sends M as `main` (F2 and N4 of the second round, closed).

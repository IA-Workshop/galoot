**Non-blocking**
- N1. The `;` paragraph in `cmake/galoot_testing.cmake` says splitting "errs on the strict side"; that holds for FORBID but splitting a REQUIRE value is looser. Say so, or reject `;` in REQUIRE as MESSAGE does.
- N2. Trace rows with a malformed item cell (`1.l`, `**1.2**`) are skipped as if they were the header; a mistyped yes row passes whenever its item has another row. Flag such lines after the separator.
- N3. Mutation coverage is per line, not per part: narrowings of `docs/agent(?!/records)`, `docs/agent(?!/records/performance)`, `spike-<letters>`, `reviews N`, `.md` and `§` after a document name, model and agent names, the `;`, `and`, `to` separators, `research-note`, `lessons learned`, `findings [D-Z]N`, bare document names, and a leader stripping only `//` survive. Add fixture lines for these, at least the compile.tsv and records path and a split across `#` lines.
- N4. `galoot_expected_findings` accepts an empty file and the rejecting test then passes on exit 1 alone; fail at configure on an empty list. The rejecting tests do not fail on unexpected extra findings (pre-existing; today's files are exact).
- N5. The copy step has no `set -e` or `&&`, so a failed `measure read` or `cmp` still appends rows; it does not say a gate tree must be a clean build; a stale cache or a stray `-D` override writes into the committed record silently. A configure-time warning when the record is not under the build tree would catch both without naming an agent path.

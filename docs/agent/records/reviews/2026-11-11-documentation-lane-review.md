## Findings

No blockers and no majors. Six minor findings, all in text, none changing a compiled example.

1. **Minor. An untraceable claim on the limits page.** `docs/guide/limits.md:360`: "A raised limit costs compile time and memory in proportion to the work it admits." Neither the header comments, `limits-removed.md`, nor any record states this, and the claim trace's row "Raising the limits" cites only the defaults and flags. Plan section 4.6 and the brief require every claim on this page to be a quoted measurement or a derivation. Scenario: a user raises `-fconstexpr-steps` for a layout and reads "in proportion" as a measured promise; no measurement exists. Fix: drop the sentence, or say "costs compile time and memory" without the proportion, and trace it.
2. **Minor. The chain-failure rates are stated without their scope.** `docs/guide/limits.md:417-421` gives 0.2%, 2.2%, 11.4% and 22.7% for conformal(3) chains; the contraction record (section 1 item 6, "Not tested") says those rates are for uncontracted builds, and the page's L1/L2 paragraphs just above say contraction changes bits. A reader on `-ffp-contract=fast` cannot tell whether the rates apply. Fix: add "in a build without fused multiply-add" (the figures come from the check's own header comment, so the scope is the presets').
3. **Minor. The page quotes a result for a toolchain it says is untested.** `docs/guide/limits.md:183` ("Clang with libc++ ... builds it") against `:429-431` ("each with libstdc++ ... Other compilers, standard libraries, and platforms are not tested"). The libc++ result comes from the removed header text. Scenario: a reader asks whether libc++ is supported. Fix: say "reported once with libc++, not a tested configuration" or drop it.
4. **Minor. A constant named `e12` for the twelfth generator.** `docs/guide/limits.md:56-59` and the comment at 66 to 68 ("e1 e12", "e2 e12"): on a page that explains that `e12` is ambiguous above 9 generators, the example names the mask of generator 12 `e12`, which the rest of the guide reads as e1 e2. The example compiles and is correct, but it is the idiom the page warns against. Fix: name it `g12` or `e_12` in the example.
5. **Minor. Two README claims are not in the claim trace.** `README.md:85`: "uses no compiler extensions" (supported by `CMakeLists.txt:11` and `-pedantic-errors`, which I checked) and the same phrase in `limits.md:429`. The trace row "Toolchains" and the README rows do not list it. Fix: add the row.
6. **Minor (process, not the branch's text). Two things the trace and decisions rely on are not on this branch.** The trace cites `records/numerical/0040-contraction-check.md` and decision 0243, which exist only on `develop`, and `limits-removed.md`, which exists only on `feature/pre-release-core-pass--comments2`; the links resolve once those merge, so the merge order matters (this branch's tip does not stand alone as a traceable record). Decision 0241 item 4 says the release record lists the FetchContent placeholder as a must-fill; no release record on this branch does (`docs/agent/records/release/` has no such row), and the plan keeps this lane out of that file. The coordinator should add the row, or the placeholder reaches the release unlisted.

### F1 (minor). An empty argument runs the real merge and tag

- Line 54: `case "${1:-}" in ''|--dry-run) ;;` accepts `""` as if no argument had been given.
- What goes wrong: `close-out-1.0.1.sh ""` (for example a script or alias that passes an empty variable) merges and tags, exit 0 (`logs/inj-arg-empty.txt`). The checks still run, so the release is correct, but the owner did not ask for it yet. Every other wrong form is refused.
- Smallest fix: `[ $# -eq 0 ] || [ "$1" = --dry-run ] || fail "usage: close-out-$V.sh [--dry-run]"` in place of line 54.

### F2 (minor). When `main` moved during the run, the printed push still sends `main`

- Lines 140 to 143.
- What goes wrong: in the race, the release is the checked commit, but `git push --atomic origin main master 1.0.0 1.0.1` would publish `main` = `9906ad90`, a change outside `docs/agent/` that no check saw, on the remote's default branch. The note says so, but the command is the same as in a clean run.
- Smallest fix: print the checked commit as the source, `git push --atomic origin $M:refs/heads/main master $PREV $V`, always (it is the same push when `main` did not move), and keep the note.

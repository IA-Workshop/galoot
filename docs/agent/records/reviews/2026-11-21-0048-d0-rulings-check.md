## Findings

1. **Minor, confirmed. Check 5 in the README says more than section 3.** `README.md:396` reads: "A precondition that stays on a declaration, as each place in the first table of Preconditions kept in full does, appears in its entry in the same words." Section 3 says only "A precondition that stays on a declaration appears in its entry in the same words". The parenthesis claims that each of the 28 places is on a declaration that has an entry. 17 are not:
   - 14 are `///` comments on `detail` helpers, with no reference entry;
   - `basis_change.hpp:258-259` is a `//` comment in `detail`;
   - `assert.hpp:30-32` and `bits.hpp:14-15` are prologue text, on no declaration.

   **Failure:** U9's author designs check 5 from this record over all 28 places. Either the test cannot pass, or it pulls generator contracts into the guide, which item 4.2 keeps out. **Fix:** "as each place in the first table that is on a declaration with a reference entry does", or drop the parenthesis. Does not block.
2. **Minor, confirmed. The README says less than section 3 in two places.**
   - The second process rule drops "and the blind reviewer's checklist asks for it" (`README.md:400`).
   - The section binds "Phase 4" and "the rows that wait for the amendment" (`:390`, `:400`). Section 3 says "no unit removes a contract from a header".

   **Failure:** a unit other than phase 4, or a row that waits for D3 alone and holds contract text (finding 3), reads as outside the condition. **Fix:** restore the reviewer clause, and say "no unit" as the decision does. Does not block.
3. **Minor, plausible. The branch's new criterion for "D3 and the S11 amendment" is not applied evenly.** Commit `8cb8803` and the README's new definition of that wait ("contract text a user needs", `README.md:90`) keep `assert.hpp:77-83` and `mv.hpp:880-882` under the amendment, because each is "the only statement in the headers of something a user meets". Rows of the same kind wait for D3 alone:
   - `linear.hpp:51-53`: the derived-class rule for sums and scaling. The delta check found that no other header line states it.
   - `unary.hpp:25-27`: the same rule for the involutions.
   - `product.hpp:35-43`: the products' operand rule and the requires-expression caveat. README loss 6 says this "moves to the reference".
   - `mv.hpp:895-899`: the guarantee that products agree between constant evaluation and run time unless multiply-adds are fused. It sits in the same comment as `:880-882` and is stated in no public comment.

   These rows were classed before this branch. Prologue text is not a declaration's `///` comment, so S11 does not reach it, and that reading may be right. **Failure:** once D3's pages pass review, a unit deletes the operand rule from `product.hpp`'s prologue before any no-drift check exists, while the same kind of text on `GALOOT_ALWAYS_INLINE` is held back. **Fix:** either move these four rows to "D3 and the S11 amendment", or narrow the README's definition to declaration comments and note why `:880-882` is kept anyway. Does not block. The choice is the coordinator's (open item 2).

As "public contract", 7 lines would move between two rows of the by-kind table. Pre-existing, but the commit rewrote the row.

Item 4.4 ruled two named places and stated no general rule. No other row is affected at `01dce7f` (check 2), but a later floating precondition would be judged by a rule the owner did not state.

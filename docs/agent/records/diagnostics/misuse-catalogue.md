# The misuse catalogue of the core

Status: ratified by the owner (decision 0196 item 5, recorded in decision 0205). Written 2026-11-08 by Claude (agent, Opus 5.5, implementer of plan 0022 part 1), against the core and tests at `b72321d` (no change to `include/` since `bd60589`). Part 3's rows and the formatter's (plan 0022) were added by the same rule on 2026-11-08, after the ratification, at `17c9baa`; they are listed in the merge report.

DoD-19 of plan 0001 asks for "a ratified misuse catalogue (mixed algebras, unknown blade, duplicate blade, n out of range, graded signature, asymmetric form, implicit lossy conversion, non-scalar type, odd+even versor in `transform`)" in which each misuse "has a compile-fail test on both compilers, matching the literal message". This record lists, under those nine items, each rejection the core makes, the message or compiler text that its tests require, and the tests. Every rejection outside the nine items is listed after them, by header.

## How it was made and how to check it

`catalogue/scan.py` reads every `static_assert` literal, `GALOOT_ASSERT` message, and `#error` text of `include/galoot/core/`, and the commands of every test in CTest's JSON listing of a configured tree (`ctest --show-only=json-v1`), one listing per compiler, and says which tests pin each message. Its rules are in its docstring; `python3 -I scan.py --self-test` runs it on the fixtures beside it, which fail if FORBID literals are counted, if a test marked WILL_FAIL is counted, if the character that stands for `;` is not read as `;`, if comments or the macro's own definition are read as assertions, or if a literal that is a part of several messages is counted for one. Its output at `17c9baa` is `catalogue/scan-output.md`. With `--check misuse-catalogue.md`, it checks that every test named in backquotes here is a test of both listings.

Commands, from the worktree root, after configuring `gcc-debug` and `clang-debug`:

```bash
ctest --test-dir build/gcc-debug --show-only=json-v1 > gcc-debug.json
ctest --test-dir build/clang-debug --show-only=json-v1 > clang-debug.json
python3 -I docs/agent/records/diagnostics/catalogue/scan.py include/galoot/core \
  gcc-debug=gcc-debug.json clang-debug=clang-debug.json \
  --check docs/agent/records/diagnostics/misuse-catalogue.md
```

Result at `17c9baa`: 153 distinct messages; 133 pinned by at least one test in each listing, the same tests in both; 20 pinned by none, each listed below with its reason; one assertion without a message (`blade_set.hpp:85`, an internal invariant). Every compile-fail test runs in every preset, so each GCC preset and each Clang preset runs it; where the required text differs by compiler, the test's CMake chooses it by `CMAKE_CXX_COMPILER_ID`, and the row says so.

Three items are met by the compiler's own text, not a library literal, by earlier design: the implicit conversion between layouts, a tag that is not an algebra given to `mv` or a plan (`blades` now names it with a literal), and narrowing in brace initialization.

## How it was made and how to check it

`tools/catalogue` (until plan 0029 part C1, the scan `catalogue/scan.py` in this directory, which read only `include/galoot/core/`) reads every `static_assert` literal, `GALOOT_ASSERT` message, and `#error` text of the headers under an include root, and the commands of every test in CTest's JSON listing of a configured tree (`ctest --show-only=json-v1`), one listing per compiler, and says which tests pin each message. Its rules are in its docstring. `tools.catalogue` tests it on the fixtures in `test/tools/catalogue/`: it fails if FORBID literals are counted, if a test marked WILL_FAIL is counted, if the character that stands for `;` is not read as `;`, if comments or the macro's own definition are read as assertions, if a literal that is a part of several messages is counted for one, if a header below the root is missed, or if the internal list's checks accept a missing message, a stale entry, or a pinned entry. `catalogue/scan-output.md` is the tool's output at `cce3496`, after the N6 message pass and the fixes its blind review asked for; before it, at `a2cad6f`, it added the delta review's three overflow tests (at `c634077` its message table was the same, but its count of test names was taken before the rows that name the review rulings' tests; before it at `a83eec3`, and at `404f2fc`) (at `f1ed6f1`, unchanged at `e248bf1`, before the change of basis); the scan's output at `7c07cc4`, from before the move, is in version control. With `--check misuse-catalogue.md`, it checks that every test named in backquotes here is a test of both listings; that step reads this record, so it stays a record step and is not a CTest.

`tests.messages_pinned` runs in every build preset: `tools/catalogue pinned` over `include/galoot/` against its own tree's listing, failing on a message that no test pins and that `test/internal_messages.txt` leaves out, on an entry of that list that no header holds or that a test pins, or on a test that requires a part of a longer message without forbidding the longer one. The list holds the messages of the last section below, with their reasons. Since it reads `include/galoot/`, the rga3 preset's six messages are in its count and in their section below.

Commands, from the worktree root, after configuring `gcc-debug` and `clang-debug` (a listing may be the build tree itself, which the tool reads with `ctest`, or a file that `ctest --show-only=json-v1` wrote):

```bash
tools/catalogue report include/galoot \
  gcc-debug=build/gcc-debug clang-debug=build/clang-debug \
  --check docs/agent/records/diagnostics/misuse-catalogue.md
tools/catalogue pinned include/galoot build/gcc-debug test/internal_messages.txt
```

The report names places by their path from the root (`core/bits.hpp:41`), where the scan at `7c07cc4` named them from `include/galoot/core/` (`bits.hpp:41`).
